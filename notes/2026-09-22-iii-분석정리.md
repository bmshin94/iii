## 1. iii는 무엇인가

- **정의**: 백엔드 통합 엔진(backend unification engine). 큐 / 크론 / HTTP API / 상태 저장 /
  pub-sub / 관측(observability) / 샌드박스 / AI 에이전트를 **하나의 런타임** 위에서 다룬다.
- **제작**: Motia LLC (`iii-hq`). 현재 버전 **v0.24.0**, Rust edition 2024.
- **슬로건**: CODER = Compose / Observe / Discover / Extend / React.
- **문제 정의**: 서비스가 N개면 통합 엣지는 N(N-1)/2개. 4개면 6개, 20개면 190개.
  이 "제곱으로 늘어나는 통합 비용"을 0에 가깝게 만드는 것이 목표.

### 3개의 프리미티브

| 프리미티브 | 정의 | 비유 |
| --- | --- | --- |
| **Worker** | 엔진에 접속해 트리거와 함수를 등록하는 프로세스 | 주방 |
| **Trigger** | 함수를 실행시키는 계기 (HTTP, 크론, 큐, 상태변경, 스트림, 직접 호출) | 주문 벨 |
| **Function** | `orders::validate` 처럼 고유 ID를 가진 작업 단위 | 요리 한 접시 |

핵심 설계 포인트: **"무엇을 하는가(Function)"와 "언제 하는가(Trigger)"가 완전히 분리**된다.
HTTP로 받던 함수를 크론으로 바꾸려면 `registerTrigger`의 `type`만 바꾸면 된다.

### 대표 사용 흐름

```bash
iii compose --namespace dev --up
iii trigger -n dev compose::add worker=queue
iii trigger -n dev compose::add worker=agent
```

워커를 추가하면 살아있는 카탈로그에 즉시 등록되고, 다른 모든 워커가 알림을 받아 바로 호출할 수
있다. README 표현: **"`compose::add`는 시스템의 npm 순간(the npm moment for systems)"**.

### 첫 워커 (TypeScript)

```typescript
import { registerWorker } from "iii-sdk";

const iii = registerWorker(process.env.III_URL ?? "ws://localhost:49134");

iii.registerFunction("hello::greet", async (input) => ({
  message: `Hello, ${input?.name ?? "world"}!`,
}));

iii.registerTrigger({
  type: "http",
  function_id: "hello::greet",
  config: { api_path: "/hello", http_method: "POST" },
});
```


## 4. 플러그인? 스킬? MCP?

**결론: 셋 다 아니다. "런타임 + CLI"이며, 그 안에 에이전트 스킬이 포함되어 있다.**

| 구분 | 해당 여부 | 설명 |
| --- | --- | --- |
| 플러그인 | ❌ | 무언가에 끼워넣는 것이 아니라 스스로 호스트다. 오히려 iii에 워커를 꽂는다 |
| Agent Skill | 🟡 일부 포함 | `skills/`에 6+1개. iii를 설명하는 문서이지 iii 자체는 아니다 |
| MCP | ❌ | MCP는 LLM↔툴 표준. iii는 자체 WebSocket 프로토콜(`engine/src/protocol.rs`)을 쓰며 목적도 "시스템 전체 운영"이다 |

정체 요약:

```
iii = ① Rust 런타임 엔진(프로세스 오케스트레이터 + 메시지 라우터)
    + ② CLI (compose / trigger / project / console)
    + ③ 4개 언어 SDK
    + ④ 워커 레지스트리(workers.iii.dev = 시스템용 npm)
    + ⑤ 개발자 콘솔(웹 UI)
    + ⑥ 에이전트 스킬 세트
```

가까운 비유: Docker Compose + Temporal + Zapier + npm + Datadog 를 한 바이너리에 합친 것.
MCP를 대체하려는 것이 아니라, 필요하면 MCP 서버를 워커로 감싸 iii 안에 넣으면 된다.

## 5. API 토큰이 필요한가

**엔진 자체는 토큰 불필요.** 로컬에서 그냥 동작한다.

### 토큰 없이 되는 것

엔진 설치/실행, 로컬 워커 등록, 함수 호출, 콘솔 열기, `workers.iii.dev` 공개 워커 다운로드,
문서/스킬/SDK 전부.

### 토큰·키가 필요한 것

| 상황 | 필요한 것 | 위치 |
| --- | --- | --- |
| AI 에이전트(harness) 사용 | `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / DeepSeek / Kimi / OpenRouter / xAI / z.ai / GitHub Copilot 중 하나 | 프로젝트 `.env` |
| OpenAI Codex 방식 | API 키 없이 ChatGPT 구독 사용 (`codex login` → `~/.codex/auth.json`) | — |
| llama.cpp (로컬 모델) | 키 없음, 완전 로컬 | — |
| 외부 API 워커 (Slack, Notion 등) | 해당 서비스 키 (`--need-envs`로 설치 중 입력 가능) | `.env` |
| RBAC 공개 리스너 | 직접 구현한 인증 미들웨어 함수 | `middleware_function_id: auth::middleware` |
| iii Cloud 배포 | iii Cloud 자격증명 | `iii cloud deploy` |

### 보안 관련 발견

1. **RBAC 내장** — 내부/외부 리스너 분리 패턴이 권장됨

   ```yaml
   iii-worker-manager:             # 내부 전용
     host: 127.0.0.1
     port: 49134
   "iii-worker-manager#rbac":      # 외부 노출 + 인증 미들웨어
     host: 0.0.0.0
     port: 49135
     middleware_function_id: auth::middleware
   ```

2. **호출 서명 검증** — `engine/src/invocation/signature.rs`
3. **SSRF 방어** — `engine/src/invocation/url_validator.rs`
4. **텔레메트리 주의** — `engine/src/workers/telemetry/amplitude.rs`가 Amplitude로 사용 통계를
   전송하고 `onboarding.rs`가 온보딩 단계까지 보고한다. 사내 도입 시 정책 확인 필요.
   (`--no-update-check`로 업데이트/보안 권고 확인은 끌 수 있다.)
5. **비밀값 규칙** — `AGENTS.md`에 "Never: Commit secrets, API keys, or credentials" 명시.

## 6. 왜 GitHub에서 유명한가

1. **Trendshift 트렌딩 배지**(`repositories/22583`)가 README 최상단 — 실제로 트렌딩에 올랐다.
2. **AI 에이전트 시대와 타이밍이 맞았다** — "에이전트 = 워커, 도구 = 함수, 기억 = 상태,
   오케스트레이션 = 트리거"라는 깔끔한 답. 기존 프레임워크가 'LLM 래퍼'인데 iii는
   '에이전트가 사는 런타임'을 자칭한다.
3. **카피가 인용하기 쉽다** — "npm moment for systems", "제곱의 통합 비용을 0으로",
   "4개=6엣지, 20개=190엣지", "CODER".
4. **진입 장벽이 거의 없다** — `curl | sh` 한 줄, 의존성 없는 단일 바이너리,
   `--learn-iii`로 5분 데모.
5. **4개 언어 SDK + 브라우저 워커** — "Raspberry Pi도, microVM도, 브라우저 탭도 같은 워커".
6. **레포 자체가 '에이전트 친화 레포'의 모범 사례** — `AGENTS.md`의 Always/Ask First/Never
   3단 가드레일, `skills/`, `.mdx.skill.md` 쌍둥이, `.cursor/rules`, `.coderabbit.yaml`,
   `.skill-check.yaml` CI 검증. 이 구조를 배우려고 구경 오는 사람이 많다.
7. **Motia 팀의 후속작**이라 초기 관심을 승계했다.
8. **엔지니어링 품질** — 벤치마크 14종, 워크플로우 30개, 버전별 문서 14세트, Terraform,
   4개 OS 패키징.
9. **ELv2 논쟁** — "이게 진짜 오픈소스냐" 논쟁 자체가 노출로 이어졌다.

## 7. 로컬 에이전트 구축에 도움이 되는가 → 매우 그렇다

### 이미 제공되는 것

| 필요 | iii 제공 |
| --- | --- |
| 에이전트 실행 루프 | `harness` 워커 (콘솔 안에서 코딩 에이전트 실행) |
| 멀티 LLM 라우팅 | `llm-router` + `provider-anthropic` / `provider-openai` / `provider-deepseek` 등 |
| 안전한 코드 실행 | `iii-sandbox` 워커 (이미지 allowlist, 유휴 타임아웃, CPU/메모리 제한, 동시 개수 제한) |
| 도구(Tool) 정의 | Function (`iii trigger my::fn --help`로 스키마 조회 가능) |
| 에이전트 기억 | `state` 워커 (`state::get` / `state::set`, 파일 기반 또는 Redis) |
| 작업 큐 | `queue` 워커 (`durable:subscriber`) |
| 스케줄링 | `cron` 워커 (7-field: 초 분 시 일 월 요일 연) |
| 실시간 스트리밍 | `iii-stream` 워커 (토큰 스트리밍에 적합) |
| 추적/디버깅 | `observability` 워커 (OpenTelemetry + 트레이스 저장 + 웹 UI) |
| 권한 제한 | RBAC 세션/설정 |
| 멀티 에이전트 | 워커 여러 개 |

### 구축 순서

```bash
iii project init my-agent --template harness
cd my-agent
nano .env                 # ANTHROPIC_API_KEY=... (또는 로컬 모델이면 생략)
iii compose --up
open http://127.0.0.1:3113
iii trigger compose::add worker=state
iii trigger compose::add worker=iii-sandbox
iii trigger compose::add worker=queue
```

### 완전 로컬/무료 구성

`llama.cpp 워커(로컬 LLM) + state(파일 기반) + sandbox(로컬 컨테이너) + observability`
→ 외부 API 키 없이 동작. 단 텔레메트리 설정은 확인할 것.

### 결정적 장점

- **에이전트가 런타임에 스스로 능력을 확장**한다 (`compose::add worker=<필요한 것>`).
  일반 프레임워크는 개발자가 코드를 쓰고 재배포해야 한다.
- **관측이 기본 제공**된다. 에이전트가 무엇을 호출했고 왜 실패했는지 트레이스로 남는다.

### 단점

- 새 멘탈 모델 학습 필요 (다만 프리미티브가 3개뿐이라 작다)
- v0.24.0 → 파괴적 변경 가능성 (`docs/upgrading/` 존재가 증거)
- 커뮤니티/예제가 아직 작아 소스를 직접 읽어야 하는 경우가 있다
- 엔진 ELv2 제약

## 8. React / PHP로 만들 수 있는가

### React — 1급 지원 (가능)

근거: `iii-browser-sdk` 공식 존재 / `console/packages/console-frontend`가 React /
`engine/src/workers/observability/ui/page.tsx`가 React / `skills/presentation`이 Vite+React+TS.

세 가지 사용 방식:

1. **일반 프론트엔드** — React → fetch → http 워커(3111), 실시간은 `iii-stream`(3112) 구독
2. **브라우저가 워커** — React 앱이 `registerWorker`로 엔진에 접속해, 백엔드가 브라우저 안의
   함수를 호출 (화면 캡처, 로컬 파일 접근, 사용자 확인 요청 등이 자연스러워진다)
3. **커스텀 콘솔** — `console-frontend`가 Apache-2.0이라 포크해 브랜딩 가능

### PHP — 공식 SDK 없음, 3가지 우회로

| 방법 | 내용 | 난이도 |
| --- | --- | --- |
| A. 소비자로 사용 | PHP(Laravel/순수/WordPress)가 Guzzle 등으로 http 워커(3111) 호출. 워커는 못 되지만 기능은 전부 사용 | 쉬움 |
| B. 사이드카 패턴 (추천) | 얇은 Node 워커가 iii에 등록되고 내부에서 PHP-FPM/Laravel 엔드포인트를 호출. PHP 코드는 그대로 두고 iii 생태계에 편입 | 쉬움~중 |
| C. PHP SDK 직접 구현 | 스펙 공개(`docs/next/reference/engine-protocol.mdx`, `engine/src/protocol.rs`). WebSocket 클라이언트(`ratchet/pawl`, `amphp/websocket-client`) + 이벤트 루프(ReactPHP/Swoole/Amp) 필요. PHP의 요청-종료 모델과 지속 연결이 잘 맞지 않는 것이 관건 | 중~상 |

### 티어 1 — 즉시 착수 가능 (1~4주)

1. **한국 특화 워커 판매** (최우선 추천)
   - `workers.iii.dev`에 한국 서비스 커넥터가 사실상 0개 → 선점 기회
   - 후보: `kakao-alimtalk`(알림톡), `toss-payments`/`portone`, `naver-commerce`/`coupang-openapi`,
     `kakao-channel`/`naver-works`, `korean-address`(도로명주소), `nice-cert`(본인인증)
   - 모델: 무료(기본 발송, 오픈소스) → Pro $9~29/월(재시도 정책, 템플릿 UI, 배치, 대시보드)
     → Enterprise $199+/월(온프레미스, SLA, 우선 지원)
   - 장점: 오픈소스 무료 버전이 마케팅, 레지스트리가 무료 유통 채널, 혼자 1~2주면 제작,
     엔진 밖이라 라이선스 자유
2. **PHP SDK 오픈소스 선점**
   - 1단계 `iii-php-sdk`(Apache-2.0) 공개 → 2단계 WordPress 플러그인 "iii Connect"
     (유료 애드온 $49 일회성 / $9월) → 3단계 Laravel 패키지 + 유료 스타터킷
     → 4단계 PHP 진영 iii 도입 컨설팅 선점
3. **템플릿 / 스타터킷 판매** (`scaffolder-core` + `--template` 구조 활용)
   - `iii-saas-starter` $79~149 / `iii-agent-starter` $99~199 /
     `iii-commerce-automation` $149 / `iii-crawler-pipeline` $59
   - 유통: Gumroad, Lemon Squeezy, Polar → 패시브 인컴
4. **에이전트 스킬팩 판매** — "한국 커머스 자동화 스킬팩", "iii 마이그레이션 스킬팩"
   ($29~79, 팀 라이선스 $299)

### 티어 2 — 현금화 최속 (1~3개월)
